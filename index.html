SEC-02 THE REFUSAL

Session b7 names the standard

Answer from the sources, or not at all. A system that will always produce something is not grounded, it is fluent. The ability to decline is the feature, not a gap in coverage.

What grounding actually requires
every claim -> a retrieved chunk every chunk -> a citation no chunk -> no answer
This is also what makes a RAG system auditable. A citation is a claim someone else can check.

SEC-06 WHERE RETRIEVAL QUIETLY FAILS

The chunk boundaryThe answer was split across two chunks, so neither one contains it. Ask: what happens to a table, or a clause, at the cut?
Meaning is not enoughSemantically close, factually the wrong document. Wrong year, wrong entity, wrong version. Ask: is there metadata we should be filtering on?
Top-k too narrowThe right chunk was ranked seventh and k was five. Ask: do we retrieve wide and then rerank?
Confidently ungroundedThe model answered anyway, from its own memory, in the same tone. Ask: can this system decline?
None of these announce themselves. They all return a fluent answer, which is exactly why session b9 exists.

SEC-07 WHAT GOOD MEANS

Session b9 makes it measurable

Judging a RAG system means judging two things separately: whether the right context was retrieved at all, and whether the answer stayed inside it. A single end-to-end score hides which half broke.
